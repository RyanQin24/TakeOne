# TAKE ONE

A robotic filming rig and its production software: one driven cart carrying an
independent phone (camera) arm and an independent light arm, both standard
SO-101 kits with custom holders. The software plans camera moves, rehearses
them in a browser simulator against calibrated arm ranges, and — only through
explicit, supervised commands — plays them back on the physical robot.

Everything runs locally. The simulator never opens a serial port, and no
software check ever claims hardware readiness: physical qualification is a
separate, human-supervised workflow with its own evidence trail.

## The production surfaces

Start the simulator (below) and open `http://127.0.0.1:8766/`.

The primary workflow is four steps — **01 Director → 02 Shot Studio →
03 Record → 04 Edit**. Director and Shot Studio carry a **TO** control for a
live conversation; Record has **Start voice control** for filming commands (see below).

| Route | Surface | Purpose |
| --- | --- | --- |
| `/` | Shot Studio | Movement library (39 presets), drawn ground paths, orbit study, previews, robot preparation |
| `/director.html` | Director | Idea → brief → script → shot proposals (optional OpenAI-backed planning) |
| `/record.html` | Record | Witness monitor beside the planned frame, framing gate, takes and review |
| `/voice.html` | Voice Rehearsal (Utilities) | Scripted read-through; offline fixture |
| `/motor-test.html` | Motor Lab (Utilities) | Direct calibrated joint diagnostics, per-motor sliders, raw-count export |
| `/drive-proof.html` | Motion Proof (Utilities) | Cart movement evidence, equations and limits (generated by `verify_drive.py`) |
| `http://127.0.0.1:5178/` | Editor | Timeline, preview, render, export — a separate local process (`takeone.editor.cli serve` + Vite) |

Completed Blackmagic phone takes can save their original files automatically to
`data/phone-sync` over a trusted USB connection. See [USB saving setup and retry
behavior](docs/phone-usb-transfer.md). Keep the iPhone connected and TakeOne running;
the Edit page shows transfer progress and refreshes saved clips automatically.

## Live person tracking

The Shot Studio **Follow a person** panel offers **Robocart · body tracking**
with optional phone/light arm tracking, and **Roboarm only · face tracking**.
The active person-tracking source is the cart-mounted Live Streamer CAM 313,
selected by its exact DirectShow name. A camera-only calibration stores the
desired shoulder midpoint and upper-body size before a live run.
**Start live tracking** explicitly launches the supplied script on real hardware.
**Stop tracking**, **Esc**, or **Q** in the camera window ends the script; arms
retain their last commanded goals. Tracking and normal robot playback cannot
run concurrently. The supplied tracking scripts are preserved byte for byte.
See [runtime setup, controls and logs](docs/live-tracking.md).

The upgraded light arm uses the operator's latest min/max ranges, including
shoulder-lift minimum **1684** and wrist-flex range **547–2879**. Shot Studio
starting goals are **1880, 2900, 2472, 1669, 2629**. Restart the app and prepare
a new plan after a calibration change. See [the calibration record](docs/light-arm-calibration-2026-09-17.md).

## TO — live voice direction

On **Record**, click **Start voice control**, allow microphone access, and say
**start filming** to run the selected shot with the iPhone. Say **stop filming**
or **cut** to stop. These commands share the button's readiness checks and use
the browser's speech service without a Gemini key. Keep the Record tab visible;
Chrome is the intended browser. See [Record voice commands](docs/record-voice-control.md).

Press **TO** in the Director or Shot Studio header to talk to the director. The browser
connects to Gemini Live directly with a single-use token minted by the local
server; the persona, tool set and context compression are locked server-side,
and every durable decision (proposing a shot, revising the script, starting a
take) is a validated tool call back to loopback. TO compiles movements before
promising them, refuses out-of-range requests by naming the field, goes
completely silent while a take records, and can request a single camera frame
when framing genuinely needs eyes. Nothing TO does can start the physical
robot — that remains the operator's explicit **Run on robot** press.

Enable it in `configs/voice-live.json` (`"enabled": true`) with `GEMINI_API_KEY`
set in the server environment. The server pre-warms the movement-preview cache
at startup so voice-requested compiles answer in ~40 ms instead of ~2 s
(`--no-prewarm` opts out; `python -m takeone.previs.prewarm --demo FILE` warms
an exact demo path). Recorded takes remember the plan that produced them and
can be scored against it at `POST /api/recording/takes/<id>/review` — vision
model when configured, honest local pixel statistics otherwise. See
[the feature record](docs/voice-live-feature-09.md).

## Quick start

Run from the checkout root in PowerShell. Setup requires Python 3.13, `uv`
and Node/npm; it leaves the separate LeRobot Python 3.12 environment alone.

```powershell
.\scripts\Setup.ps1                          # install/reconcile the root environment
.\scripts\TakeOne.ps1 -Command simulator     # serve http://127.0.0.1:8766/  (Ctrl+C stops)
.\scripts\TakeOne.ps1 -Command diagnose      # saved device identities and readiness blockers; no ports open
.\scripts\TakeOne.ps1 -Command dry-run       # compile and validate the default plan offline
.\scripts\TakeOne.ps1 -Command test          # product tests, simulation regressions, web checks, lint
```

Use `-Port 8768` for a second simulator. The server watches its own sources
and restarts cleanly when they change. `TAKEONE_ROOT` can point at another
complete configuration/assets checkout with the same layout.

Director scripts can stage separate locations with seven atmosphere choices,
supporting cast and 21 reusable scene objects. Film language covers palette,
lighting, wardrobe, sound and continuity; each shot carries its purpose, nine
available framing sizes, focus intent and timed performance beats. The Director
can fit a fixed lens from the solved camera pose or preserve an authored lens.
Shot Studio checks subject coverage, displays the current performer cue, and
exports a shooting guide with lens choices and achieved camera heights.

Shot Studio offers a filming-only
story edit and a setup-inclusive rehearsal. Location changes are cuts with
off-camera resets; same-location drives are explicit. The maintained directing
instructions are [Markdown skills](packages/takeone/director/robot-film-director/SKILL.md).
Cart-follow and head-follow choices currently call for pending controller
integrations; their preview uses scripted actor movement. See the
[script-to-scene audit](docs/ai-director/implementation/05-scene-aware-script-audit.md).
The [shot-language implementation record](docs/ai-director/implementation/07-shot-language.md)
explains the loaded design and review skills, actor choreography, reproducible
exercise, and the limits of simulated evidence.

The editor runs as its own process:

```powershell
.\.venv\Scripts\python.exe -m takeone.editor.cli serve --media-root data/takes
cd apps\editor; npm install; npm run dev    # interface on http://127.0.0.1:5178/
```

## Working with the real robot

Physical work is deliberately explicit, supervised and separate from the
simulator. The entry points, in the order they are normally used:

```powershell
# One-time: isolated driver runtime for the robot-connected Windows machine.
.\.venv\Scripts\python.exe scripts\setup_robot_runtime.py

# Commissioning launcher: encoder-maxima learning, checked approach, playback.
.\scripts\Run-Robot.ps1            # add --qualified to retain formal evidence checks

# Supported hold test (see docs/arm-commissioning.md for options and safety).
.\lerobot\.venv\Scripts\python.exe -m takeone.motion.hold --until-enter

# Exact raw motor test: export from the simulator or CLI, validate, then execute.
.\.venv\Scripts\python.exe -m takeone.direct --output data\direct-motor-test.json
.\lerobot\.venv\Scripts\python.exe -m takeone.motion.direct --plan data\direct-motor-test.json
.\lerobot\.venv\Scripts\python.exe -m takeone.motion.direct --plan data\direct-motor-test.json `
  --confirm-plan PLAN_ID --operator-ready --execute
```

The Shot Studio's **Real robot** panel prepares the current shot and starts
the cart and both arms only when **Run on robot** is pressed; **Stop**/Esc
stops travel and retains arm goals. The older shot-planning CLI
(`python -m takeone.motion.cli`: `prepare`, `check`, `preflight`, `templates`,
`assess`, supervised `live`) remains the offline checker for exported plans.
The separate [cart-only commissioning workflow](docs/cart-live-testing.md)
provides calculated command plans and a supervised `live-test` envelope.

When `configs/iphone-camera.json` is enabled and its setup is complete, both
**Run on robot** and `scripts\Run-Robot.ps1` reserve that exact phone setup,
wait for Blackmagic Camera to confirm recording before torque or movement, run
the timestamped lens cues on the reviewed shot clock, and request a confirmed
camera stop on completion, browser Stop, or a playback fault. An unreachable or
unconfirmed camera blocks motion. Use **Record > Phone setup** to connect,
calibrate at least two focal-length points, confirm the color recipe, and run
the two-second camera-only test on the robot computer before a physical take.
For zoom cadence, camera-only ramp testing and measured Wi-Fi limits, see
[iPhone zoom timing](docs/phone-zoom-timing.md).

Do not run LeRobot's normal `connect()` expecting a read-only diagnostic: it
configures motors. Follow [the hardware test runbook](docs/hardware-test-runbook.md)
before any hardware work.

## Development

The [cinematic movement upgrade](docs/ai-director/implementation/06-cinematic-channels.md)
brings the library to 38 selectable presets, with independent camera/light timing, organic drift,
cart breath, continuous takes shared across short edit beats, and product-only
subjects. Open Shot Studio's **Compound routes** or **Product study** family.
Director uses the same timing editor. Motion limits are unchanged; reposition
times are explicitly lower bounds and the light's brightness remains manual.

- `scripts/TakeOne.ps1 -Command test` runs `scripts/verify.py`: Python product
  tests, MuJoCo simulation regressions, the web test/syntax checks, the
  preservation audit and pinned Ruff lint/format checks.
- The simulator imports the installed `takeone` package directly; there are no
  path shims. After changing robot models run
  `.venv/Scripts/python.exe -m takeone.simulation.model`, then
  `node apps/rehearsal/export_models.mjs`, then the tests.
- [Arm movement design](docs/arm-movement-design.md) is the code-reading guide
  for settings, target strategies, IK, trajectory generation and validation.
- Run manifests record configuration/calibration/model hashes, requested
  commands, transmitted packets and observation-source labels. A fake
  observation or a successful serial write must never be presented as a
  measured physical movement.
- To keep versioned verification reports untouched, route a verify run
  elsewhere: `python scripts/verify.py --output-dir C:\TakeOne-verification`.

## Hardware ground truth

The physical facts the software treats as authoritative — mount heights,
wheel layout, calibration ranges, watchdog behaviour, measured maxima and the
still-unqualified items — are recorded in
[robot commissioning](docs/robot-commissioning.md),
[arm commissioning](docs/arm-commissioning.md),
[robot motion execution](docs/robot-motion-execution.md),
[the cart audit](docs/cart-audit-2026-09-12.md) and
[the parameter inventory](docs/calibration-inventory.md). The dated correction
records under `docs/` preserve the measurement history behind the current
geometry. Loaded limits, independent cart response/stopping, tool/scene
measurements and full-robot timing remain unqualified; preflight fails until
those measurements exist.

## Free, extensible scene assets

The local asset library is integrated with Director and Shot Studio. The initial
installed collection contains **687 Kenney CC0 model files**: 140 furniture,
200 food, 329 nature and 18 characters. The 21 procedural assets remain supported.
These are visualization assets, not confirmation that a prop exists on location.

In **Director > Script > Edit scene & objects**, use **Add from object library**.
Imported identifiers are validated, saved and carried into the same Shot Studio
renderer. Set each object's centre, dimensions in metres and yaw in the editor.
Browse individual models at `http://127.0.0.1:8766/asset-library/browser.html`.
No model-specific Python enumeration or rendering branch is required for imports.

```powershell
.\.venv\Scripts\python.exe -m takeone.asset_library --root C:\TakeOne search "chair"
.\.venv\Scripts\python.exe -m takeone.asset_library --root C:\TakeOne verify
.\.venv\Scripts\python.exe -m takeone.asset_library --root C:\TakeOne download --starter
```

Reviewed source records live in `configs/asset-library/packs.json`; local models,
licenses, provenance and the searchable catalog live under
`apps/rehearsal/dist/asset-library/`. Director generation uses a bounded lexical
shortlist and the original `scene-dressing/SKILL.md` instructions. Animation clips
can be inspected in the library viewer; character retargeting onto the existing
performer figures is not part of this integration.

See [the live status and evidence](docs/ai-director/implementation/08-asset-scene-status.md).
The separate authored ensemble exercise has two explicit camera-review warnings;
its existence is not a claim that all shots or physical movements are qualified.
