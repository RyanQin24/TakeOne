# Scene dressing and ensemble direction

Build a scene around a change the audience can observe, not a collection of props.
Use the existing scene objects, cast, shot design and timed performance beats. Never
invent unsupported document fields, asset IDs, animation clips or robot abilities.

## The set serves the story
Give important objects a purpose: an actor uses one, notices it, avoids it or reveals it.
Separate the main action from background activity. Foreground framing is optional and
must not obscure a promised face, hand, product or full-body region. Negative space
can be more useful than more furniture. Do not impose a minimum prop or cast count.
Use only available named performers; a downloaded character is not an available actor.

Choose model IDs from the supplied catalog shortlist. Set explicit bounding-center
position_m, positive size_m and yaw_rad in the scene's X/Y floor and Z-up metres.
A mesh is only a visualization. Set availability to present only when the user has
confirmed that physical prop; otherwise use proposed, virtual_only or unconfirmed.
Use location_notes to describe that distinction. Ask about unavailable necessities.
Keep object_id short (40 characters maximum) and independent of the long asset_id.
Keep clear actor paths and camera/cart routes; the simulator must assess the result.

## People have independent intentions
Give each participating performer a distinct objective, eyeline and observable action.
Use design.beats with the actor IDs already supported by the contract.
A partner may watch the person first and the shared object second. A background actor
can finish their own action before noticing the main event. Do not mirror the lead.
The current proxy animation is not proof of hand contact, sitting or facial expression;
write those as on-set performance directions rather than claiming they are simulated.

## Build coverage, not a parade of camera moves
Each shot must reveal new information, shift attention or change the relationship.
Consider an introduction, shared action, meaningful insert, reaction and resolution,
but omit any that do not help this particular brief. Vary durations with the event.
Choose camera motion only when it serves the change; a held reaction can be stronger.
Maintain prop ownership, screen direction, eyelines and performer positions across cuts.
Opening and ending frames should differ in a story-relevant way, not just camera size.

## Example of intent, not a fixed story template
For a team seeing its prototype finally respond: establish the shared work surface;
show an uncertain attempt; insert the actual response; hold the lead's delayed reaction;
let the partner notice; let a background teammate join afterward. Keep the real footage
and practical prototype central. Do not assert product claims not supplied as facts.
